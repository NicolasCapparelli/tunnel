# Architecture

## Components

[Desktop entry](../../apps/desktop/src/main.tsx) hosts React in a Tauri WebView with Aurora's web provider. [Bridge](../../apps/desktop/src/bridge.ts) separates native IPC from an explicitly limited browser preview. [Native main](../../apps/desktop/src-tauri/src/main.rs) owns tray, window lifecycle, shortcut, startup and listener startup. [Server](../../apps/desktop/src-tauri/src/server.rs) owns pairing, disk state, sockets, receipts, clipboard and native notifications independently of WebView visibility.

[Mobile entry](../../apps/mobile/App.tsx) loads fonts/storage and wraps Aurora, safe-area and share-intent providers. [Mobile application](../../apps/mobile/src/TunnelApp.tsx) owns navigation, foreground lifecycle, camera pairing, history and clipboard. [Connection adapter](../../apps/mobile/src/connection.ts) selects the native Android service or the shared JavaScript client for other environments. [Android service](../../apps/mobile/modules/tunnel-link/android/src/main/java/app/tunnel/link/TunnelService.kt) owns one foreground lifecycle, with independent [PeerSession](../../apps/mobile/modules/tunnel-link/android/src/main/java/app/tunnel/link/PeerSession.kt) sockets, keys, heartbeat, reconnect and receipts for each desktop. [Native store](../../apps/mobile/modules/tunnel-link/android/src/main/java/app/tunnel/link/LinkStore.kt) commits a bounded receipt inbox before acknowledgment. The JS UI consumes that inbox only while active, persists AsyncStorage history and then removes pending native entries. [Shared client](../../packages/shared/src/index.ts) owns the equivalent JavaScript protocol for other platforms/previews. React Native uses Expo native modules; desktop uses React DOM, not React Native inside Tauri.

## Pairing and delivery

Desktop creates an expiring QR with endpoint, server ID, shared key and pairing token. The phone validates a local IPv4 endpoint and performs an encrypted hello. The server binds one phone identity; subsequent reconnects retain credentials. Unlink rotates the key and disconnects. This is device pairing rather than account authentication. Editable names propagate through welcome/name frames on authenticated connections, and mobile credentials retain the current desktop name.

Text and attachment metadata/bytes are validated, assigned a stable ID, encrypted with ChaCha20-Poly1305 and sent over a local WebSocket. Receipt follows receive persistence. UI clears an unchanged draft only after confirmation. Retry retains the original ID; bounded seen-ID storage suppresses duplicate side effects. Receipt timeout indicates uncertainty, not proof of nondelivery. Desktop handles clipboard and notification errors without discarding received history. Mobile serializes persistence before receipt. See [model](../data/model.md).

## Constraints and extension boundaries

The native listener remains in the tray; Android keeps its connection in a remote-messaging foreground service after pairing; it can receive without JavaScript execution. Notifications disclose ongoing availability. Phone clipboard operations wait until the UI is active. OS force-stop/power/network restrictions remain outside app control; iOS still uses a foreground JS connection. Desktop toast activation opens history on Windows; other platforms need separate implementation/verification. Standalone Windows receipt notifications register a per-user Start Menu shortcut and AUMID through [notification identity](../../apps/desktop/src-tauri/src/notifications.rs), without requiring an installer. One paired phone, text/links and up to 250 MiB/32 files per quanta, bounded history and local IPv4 are current constraints. Manually composed drafts do not auto-send offline. Instant native Android shares have a persisted outbox tied to the original desktop identity. Continuous clipboard monitoring is not implemented.

Phone UI keys use SecureStore; the Android service stores its credential copy encrypted with an Android Keystore AES-GCM key. Native pending inbox/seen IDs use app-private SharedPreferences; history/draft use AsyncStorage. Desktop state including keys is local-user-readable JSON; no application encryption at rest. There is no backend, analytics or account requirement. The shared client's socket interface is the future remote-transport seam, but relay authentication/discovery are not implemented. [Aurora integration](../design/integrations.md) is shared across the two renderers.

## Attachment and external intake flow

[File adapter](../../apps/mobile/src/files.ts) and native [LinkFiles](../../apps/mobile/modules/tunnel-link/android/src/main/java/app/tunnel/link/LinkFiles.kt) separate private file bytes from UI history metadata. ChaCha20-Poly1305 envelopes carry a metadata begin frame, ordered 48 KiB file chunks and an end frame. Native receivers stage to disk and reject offsets/incomplete sizes; receipts follow complete file and metadata persistence. [Rust staging](../../apps/desktop/src-tauri/src/stream.rs) and [Android staging](../../apps/mobile/modules/tunnel-link/android/src/main/java/app/tunnel/link/IncomingFiles.kt) own this boundary. Both senders apply queue backpressure. The JavaScript fallback uses a bounded 5 MiB assembly path. Desktop IPC supplies native picking, bounded lazy image thumbnails, file/image clipboard and save dialogs. Android Save uses MediaStore or an API-28 document picker; Share remains separate through Expo Sharing. Receive does not execute files or automatically open them. A single received image can populate the Windows clipboard; notes retain text auto-copy behavior. Android receipts use a new high-importance channel, while availability retains its ongoing foreground notification; user permission/channel preferences still control display.

[ShareActivity](../../apps/mobile/modules/tunnel-link/android/src/main/java/app/tunnel/link/ShareActivity.kt) receives Android selected text and shared content independently of React/Metro. Per-type native settings select immediate outbox enqueue or forwarding to the existing share-intent composer. It starts the foreground transport while the intake activity is visible and closes; the service sends queued shares when connected and reports receipt/failure through notification/history. The main activity has no public SEND filter, avoiding duplicate chooser entries and bypass of instant-send policy. Direct Share targets the same native intake. iOS remains a foreground composer/transport path; native background instant sharing is Android-specific.

## Local multi-desktop routing

Authorized 2026-10-10: one Android phone can pair with multiple desktop listeners, including Windows and Mac. Each desktop retains its one-phone contract. [Registry/routing helpers](../../packages/shared/src/devices.ts) restore legacy single credentials, upsert by server ID, prune explicitly selected destination IDs and create independent recipient transfers. No desktop acts as a hub and no group key is shared.

The phone launches one connection per pairing; native sessions remain active when React is backgrounded. Normal instant intake fans out to saved destinations; device-specific Direct Share fixes the destination. Delivery IDs/history are per recipient, so retries address only the original desktop and partial success preserves successful receipts. Registry updates/unlink affect one peer; the native queue never redirects a pending share to another. A serialized JS refresh consumes the global inbox/outbox after history persistence. Legacy inbox source tags are committed before changing the original pairing. See [model](../data/model.md#multi-desktop-registry-and-recipient-identity).

[Cross-platform CLI dispatch](../../tools/desktop.mjs) retains the Windows portable-toolchain helper and uses native Tauri CLI on macOS, always embedding release assets. Mac compilation/runtime is not verified from this Windows host. Remote transport, phone-to-phone, discovery/address updates and multi-phone desktop listeners remain future scope.

## Singularity account sync

Selected 2026-10-30. Every device will own a local Entanglement SQLite database and sync it in realtime mode to the user's Cloudflare identity. [Entanglement Cloudflare adapter](../../vendor/entanglement/VENDORED.md) talks to `apps/cloudflare`: the Worker verifies the signed `Cf-Access-Jwt-Assertion`, uses its stable subject as the Durable Object name, and the per-user SQLite Durable Object implements Entanglement's commit/CAS, checkpoint, restore-point and compaction contract. Realtime WebSockets carry revision hints only; data is fetched over authenticated HTTPS. A short-lived one-use ticket authenticates the hint socket because native WebSocket APIs cannot attach the OAuth bearer header. `/v1/hints` must be excluded from Access only after enabling this ticket check; other routes remain Access-protected.

[Shared model](../../packages/shared/src/singularity.ts) defines raw quanta, spaces and entries. `openSingularity` sets realtime mode and accepts SQL.js on Windows or Expo SQLite on Android. Both panels provide raw text append/search and structured space/entry create/search. The Dusk shells keep each panel mounted across page/account navigation to retain callback listeners and runtime ownership. Raw-to-space moves write an entry and delete the raw item in one local database transaction. Shared entry-content helpers preserve full body text while deriving short preview titles. Credentials use Windows Credential Manager or Android SecureStore; account-keyed SQLite files retain offline data.

[Shared OAuth helper](../../packages/shared/src/singularity-auth.ts) uses Cloudflare Managed OAuth authorization-code/PKCE, rotating refresh tokens and revocation. The exact HTTPS callback forwards code/state to the fixed Tunnel deep link; the app verifies state and exchanges using its saved verifier. RFC 8707 resource identifies the Worker during authorization, token exchange and refresh. Optional OIDC scopes are requested only when discovery advertises them; current Cloudflare metadata advertises none. A versioned redirect/scope registration profile replaces older cached registrations once, then reuses matching clients. The helper preserves offline credentials when refresh cannot reach the network and coalesces concurrent refreshes. Sign-out revokes/clears credentials and retains local data.

Windows OAuth uses the restricted `singularity_auth_request` native command through its vault transport to avoid WebView Origin rejection. It allows HTTPS Cloudflare OAuth POSTs and workers.dev discovery/account GETs, sends no Origin/cookies, refuses redirects, applies a timeout and caps payload sizes. Android uses native fetch. Entanglement sends opaque OAuth tokens as Bearer authorization; Cloudflare validates them and the Worker verifies the resulting signed assertion/audience. Account data remains owner-protected.

The user rejected the custom native code-exchange alternative; its routes and undeployed migration were removed. No token bypass application or CORS policy change was applied. Managed OAuth remains the active sign-in path. The user confirms return to Tunnel and the Android crypto fix; authenticated sync, refresh and offline behavior remain pending device verification.
