# Architecture

## Components

[Desktop entry](../../apps/desktop/src/main.tsx) hosts React in a Tauri WebView with Aurora's web provider. [Bridge](../../apps/desktop/src/bridge.ts) separates native IPC from an explicitly limited browser preview. [Native main](../../apps/desktop/src-tauri/src/main.rs) owns tray, window lifecycle, shortcut, startup and listener startup. [Server](../../apps/desktop/src-tauri/src/server.rs) owns pairing, disk state, sockets, receipts, clipboard and native notifications independently of WebView visibility.

[Mobile entry](../../apps/mobile/App.tsx) loads fonts/storage and wraps Aurora, safe-area and share-intent providers. [Mobile application](../../apps/mobile/src/TunnelApp.tsx) owns navigation, foreground lifecycle, camera pairing, history and clipboard. [Connection adapter](../../apps/mobile/src/connection.ts) selects the native Android service or the shared JavaScript client for other environments. [Android service](../../apps/mobile/modules/tunnel-link/android/src/main/java/app/tunnel/link/TunnelService.kt) owns background WebSocket/heartbeat/reconnect/receipts. [Native store](../../apps/mobile/modules/tunnel-link/android/src/main/java/app/tunnel/link/LinkStore.kt) commits a bounded receipt inbox before acknowledgment. The JS UI consumes that inbox only while active, persists AsyncStorage history and then removes pending native entries. [Shared client](../../packages/shared/src/index.ts) owns the equivalent JavaScript protocol for other platforms/previews. React Native uses Expo native modules; desktop uses React DOM, not React Native inside Tauri.

## Pairing and delivery

Desktop creates an expiring QR with endpoint, server ID, shared key and pairing token. The phone validates a local IPv4 endpoint and performs an encrypted hello. The server binds one phone identity; subsequent reconnects retain credentials. Unlink rotates the key and disconnects. This is device pairing rather than account authentication. Editable names propagate through welcome/name frames on authenticated connections, and mobile credentials retain the current desktop name.

Text and attachment metadata/bytes are validated, assigned a stable ID, encrypted with ChaCha20-Poly1305 and sent over a local WebSocket. Receipt follows receive persistence. UI clears an unchanged draft only after confirmation. Retry retains the original ID; bounded seen-ID storage suppresses duplicate side effects. Receipt timeout indicates uncertainty, not proof of nondelivery. Desktop handles clipboard and notification errors without discarding received history. Mobile serializes persistence before receipt. See [model](../data/model.md).

## Constraints and extension boundaries

The native listener remains in the tray; Android keeps its connection in a remote-messaging foreground service after pairing; it can receive without JavaScript execution. Notifications disclose ongoing availability. Phone clipboard operations wait until the UI is active. OS force-stop/power/network restrictions remain outside app control; iOS still uses a foreground JS connection. Desktop toast activation opens history on Windows; other platforms need separate implementation/verification. Standalone Windows receipt notifications register a per-user Start Menu shortcut and AUMID through [notification identity](../../apps/desktop/src-tauri/src/notifications.rs), without requiring an installer. One paired phone, text/links and up to 250 MiB/32 files per quanta, bounded history and local IPv4 are current constraints. Manually composed drafts do not auto-send offline. Instant native Android shares have a persisted outbox tied to the original desktop identity. Continuous clipboard monitoring is not implemented.

Phone UI keys use SecureStore; the Android service stores its credential copy encrypted with an Android Keystore AES-GCM key. Native pending inbox/seen IDs use app-private SharedPreferences; history/draft use AsyncStorage. Desktop state including keys is local-user-readable JSON; no application encryption at rest. There is no backend, analytics or account requirement. The shared client's socket interface is the future remote-transport seam, but relay authentication/discovery are not implemented. [Aurora integration](../design/integrations.md) is shared across the two renderers.

## Attachment and external intake flow

[File adapter](../../apps/mobile/src/files.ts) and native [LinkFiles](../../apps/mobile/modules/tunnel-link/android/src/main/java/app/tunnel/link/LinkFiles.kt) separate private file bytes from UI history metadata. ChaCha20-Poly1305 envelopes carry a metadata begin frame, ordered 48 KiB file chunks and an end frame. Native receivers stage to disk and reject offsets/incomplete sizes; receipts follow complete file and metadata persistence. [Rust staging](../../apps/desktop/src-tauri/src/stream.rs) and [Android staging](../../apps/mobile/modules/tunnel-link/android/src/main/java/app/tunnel/link/IncomingFiles.kt) own this boundary. Both senders apply queue backpressure. The JavaScript fallback uses a bounded 5 MiB assembly path. Desktop IPC supplies native picking, bounded lazy image thumbnails, file/image clipboard and save dialogs. Android Save uses MediaStore or an API-28 document picker; Share remains separate through Expo Sharing. Receive does not execute files or automatically open them. A single received image can populate the Windows clipboard; notes retain text auto-copy behavior. Android receipts use a new high-importance channel, while availability retains its ongoing foreground notification; user permission/channel preferences still control display.

[ShareActivity](../../apps/mobile/modules/tunnel-link/android/src/main/java/app/tunnel/link/ShareActivity.kt) receives Android selected text and shared content independently of React/Metro. Per-type native settings select immediate outbox enqueue or forwarding to the existing share-intent composer. It starts the foreground transport while the intake activity is visible and closes; the service sends queued shares when connected and reports receipt/failure through notification/history. The main activity has no public SEND filter, avoiding duplicate chooser entries and bypass of instant-send policy. Direct Share targets the same native intake. iOS remains a foreground composer/transport path; native background instant sharing is Android-specific.
